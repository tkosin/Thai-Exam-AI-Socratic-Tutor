# แนวทางออกข้อสอบแนวโอลิมปิกวิชาการ ป.5–ม.3

สเปกการออกข้อสอบระดับ `แข่งขัน` และ `โอลิมปิก` ของ repo นี้
อ่านคู่กับ [`roadmap.md`](roadmap.md) (ลำดับเฟส) และ
[`../questions/topics.json`](../questions/topics.json) (แผนที่ตัวชี้วัด — ตัวตัดสินความครอบคลุม)

> ### 📌 บันทึกการปรับให้ตรงกับของจริง
>
> สเปกฉบับที่รับเข้ามาเขียนขึ้นก่อนงานสองรอบล่าสุด ตัวเลขและข้อสั่งงานบางข้อจึงล้าสมัยไปแล้ว
> ส่วนที่เป็น**หลักการ** (ข้อ 2, 3, 4, 5, 9) รับมาทั้งหมดไม่แก้ ส่วนที่เป็น**ตัวเลขสถานะ**
> (ข้อ 0, 1, 7, 11) แก้ให้ตรงกับคลังจริง รายการที่ต่างจากต้นฉบับ:
>
> | ต้นฉบับเขียนว่า | ของจริงตอนนี้ |
> | --- | --- |
> | "ไม่ต้องเพิ่มระดับใหม่ ไม่ต้องแตะ `index.html`" | **มีระดับ `โอลิมปิก` แล้ว** เพิ่มไปเมื่อรอบก่อน พร้อมป้ายสีและตัวกรองในหน้าเว็บ |
> | "วิทยาศาสตร์ไม่มีข้อระดับแข่งขันเลยสักข้อ (0/1,150)" | มีแล้ว **45 ข้อ** (ชั้นละ 15) และ `validate.py` บังคับทุกวิชาแล้ว |
> | คณิตมีแข่งขัน 136/2,548 (5.3%) | **136 แข่งขัน + 60 โอลิมปิก = 196/2,628 (7.5%)** |
> | "วิทย์ ม.1/ม.2 ยังค้าง 43 หัวข้อที่รอรูป" | **0 หัวข้อ** — รูปครบทุกตัวชี้วัดที่หลักสูตรสั่งให้มีแล้วทั้ง 6 วิชา |
> | หางยาว `verify_math.py` 726 ข้อ | **612 ข้อ** |
>
> ข้อ 0.1 ของต้นฉบับ ("ใช้ช่อง `แข่งขัน` ที่มีอยู่แล้ว") ขัดกับสิ่งที่ทำไปแล้วโดยตรง
> จึงตีความใหม่เป็น **สองชั้น** ดูข้อ 4.1 — ถ้าต้องการยุบกลับเป็นชั้นเดียวบอกได้ ทำได้ไม่ยาก
> เพราะการแก้ฟิลด์ `level` ไม่กระทบรหัสประจำข้อ

## 0. สรุปสั่งงาน (อ่านอันเดียวก่อนลงมือ)

1. **มีสองชั้นให้ใช้แล้ว: `แข่งขัน` และ `โอลิมปิก`** — เกณฑ์แยกชั้นอยู่ในข้อ 4.1
2. ช่องว่างที่วัดได้ตอนนี้: **ทุกวิชามีระดับแข่งขันแล้ว แต่สัดส่วนยังต่ำกว่าเป้า** ดูข้อ 1
3. โจทย์แนวโอลิมปิกที่ repo นี้รับได้ = **แบบตอบค่าเดียว (answer-only)** เท่านั้น ดูข้อ 2
4. หลักการเดียวที่ต้องท่อง: **ความรู้อยู่ในหลักสูตรของชั้นนั้น · ความคิดอยู่นอกหลักสูตร**
5. ทำ **ม.1–ม.3 ก่อน** (เติมของที่มีอยู่) แล้วค่อย **ป.5–ป.6** (ต้องตั้งวิชาใหม่ = เฟส 4 ของ roadmap)
6. ทุกข้อที่เพิ่ม ต้อง **เพิ่มข้อใหม่** เท่านั้น ห้ามแก้ข้อความ/เฉลยของข้อเดิม

## 4. นิยาม `แข่งขัน` — เกณฑ์ตัดสิน

ข้อหนึ่งจะติดป้าย `แข่งขัน` ได้ ต้องผ่าน **อย่างน้อย 3 ใน 5 ข้อ** และต้องผ่านข้อ (1) เสมอ

1. **โซ่การคิดยาว ≥ 3 ขั้น** — ขั้นที่ 1 ยังไม่เห็นคำตอบ และแต่ละขั้นต้องใช้ผลของขั้นก่อน
   *ไม่นับ* การแทนค่าลงสูตรเดียวแล้วคิดเลขหลายบรรทัด (นั่นคือระดับ `ยาก`)
2. **ข้ามหัวข้อ** — ต้องใช้ความรู้จากอย่างน้อย 2 หน่วยการเรียนรู้ หรือ 2 ตัวชี้วัด
3. **ไม่มีสูตรตรง** — เปิดหนังสือเรียนแล้วหาสูตรที่ใช้ได้ทันทีไม่เจอ ต้องประกอบเอง
4. **มีทางลัดถ้ามองเห็นโครงสร้าง** — คนที่เห็นสมมาตร/ค่าคงตัว/รูปแบบ ทำเสร็จใน 1 นาที
   คนที่ไม่เห็นต้องไล่ยาวแต่ก็ยังทำได้ *(คุณสมบัตินี้คือหัวใจของโจทย์โอลิมปิกจริง)*
5. **ตัวเลขปลายทางสวย** — คำตอบเป็นจำนวนเต็ม เศษส่วนอย่างต่ำ หรือทศนิยมไม่เกิน 2 ตำแหน่ง
   ถ้าคำตอบออกมาเป็น 7.3846… แปลว่าโจทย์ออกแบบผิด ไม่ใช่โจทย์ยาก

**เพดานที่ห้ามข้าม** — ความรู้ที่ใช้ต้องอยู่ใน **ตัวชี้วัดของชั้นนั้นหรือชั้นต่ำกว่า** เท่านั้น
ห้ามใช้ทฤษฎีบทนอกหลักสูตร (เช่น กฎของแอล'โฮปิตาล, ตรีโกณมิติกับ ม.1, สมการเชิงอนุพันธ์)
โจทย์โอลิมปิกที่ดีของชั้น ม.1 คือโจทย์ที่เด็ก ม.1 **มีเครื่องมือครบแล้ว** แต่ต้องคิดเอง

### 4.1 เส้นแบ่ง `แข่งขัน` กับ `โอลิมปิก`

repo มีสองชั้น เพราะสองสนามนี้ต่างกันจริงในทางปฏิบัติ ไม่ใช่แค่ "ยากกว่า"

| | `แข่งขัน` | `โอลิมปิก` |
| --- | --- | --- |
| สนามอ้างอิง | สพฐ. · สสวท. · TEDET · IJSO รอบทฤษฎี | สอวน. · TMO |
| เกณฑ์ข้อ 4 | ผ่าน **≥ 3 ใน 5** และต้องผ่านข้อ (1) | ผ่าน **≥ 4 ใน 5** และ**ต้องผ่านข้อ (4)** |
| ลักษณะเด่น | โซ่ยาว ข้ามหัวข้อ แต่ยังเดินตามเส้นทางมาตรฐานได้ | **ต้องเห็นโครงสร้างถึงจะเข้าทาง** ไล่ตรง ๆ อาจไม่จบในเวลาสอบ |
| ป้ายในหน้าเว็บ | น้ำเงินเข้ม | ม่วงเข้ม (เข้มกว่าอีกขั้น) |
| วิชาที่บังคับให้มี | **ทุกวิชา** (`validate.py` ตรวจ) | คณิตศาสตร์เท่านั้น |

**ทำไมวิทยาศาสตร์ยังไม่บังคับ `โอลิมปิก`** — ยังไม่มีชุดโจทย์วิทย์ที่มั่นใจว่าเทียบชั้น สอวน. ได้จริง
การติดป้ายโอลิมปิกให้ข้อที่ยากไม่พอ ทำให้ป้ายนั้นไม่มีความหมาย — ปล่อยว่างไว้ตรงกว่า
ถ้าจะเปิดวิทย์ระดับโอลิมปิก ให้เริ่มจาก **ฟิสิกส์เชิงคำนวณของ ม.3** ซึ่งใกล้ IJSO ที่สุด

## 5. กติกาบังคับของ repo (ละเมิดแล้ว `check.sh` ไม่ผ่าน หรือทำข้อมูลผู้เรียนหาย)

| กติกา | เหตุผล |

| **ทุกข้อต้องมี `std` ที่มีอยู่จริงใน `topics.json`** หรือ `-` | `validate.py` ตีตกตัวชี้วัดที่ไม่อยู่ในแผนที่ · ข้อที่รวมหลายหัวข้อจนไม่ผูกกับตัวชี้วัดใดใช้ `-` ได้ |
| **กรอกค่าตรงเฉลยแล้วต้องได้ "ถูกต้อง"** | ด่านของ `validate.py` |
| **ข้อคณิตต้องเขียนให้ `verify_math.py` คิดใหม่ได้** | ตัวเลขต้องอ่านออกจากข้อความโจทย์ ไม่ซ่อนอยู่ในรูป · ถ้าแม่แบบใหม่ยังไม่มีกฎ ให้**เขียนกฎคู่กันไปในรอบเดียว** ไม่ทิ้งไว้เป็นหางยาว |
| **ตัวเลขในรูปกับในโจทย์ต้องมาจากตารางเดียวกัน** | กันรูปกับโจทย์บอกคนละเลข |
| **ชีววิทยาไม่วาดโครงสร้างด้วย SVG** | ใช้ได้เฉพาะตาราง/ผัง (พันเนตต์ · สายใยอาหาร · ผังทางเดินเลือด) |
| **วิชาใหม่ต่อท้าย `courses.json` เท่านั้น** | ห้ามแทรกก่อนวิชาเดิม · ลำดับที่ผู้เรียนเห็นคุมด้วย `SUBJECT_ORDER` ใน `index.html` |
| **ตัวชี้วัด ป.5/ป.6 ต้องอ่านจากหลักสูตรจริงตอนลงมือ** | ห้ามเดาล่วงหน้า — เคยเดาตัวชี้วัดวิทย์ ม.3 แล้วผิด 10 ตัวจาก 59 |
| **เฉลยของสองระดับนี้ต้องคำนวณจากโค้ด** | ดู `tools/gen_advanced.py` — คิดสองทางแล้วเทียบกันก่อนเขียนไฟล์ ไม่พิมพ์เฉลยเอง |

### ใช้ `sub` เป็นชื่อแม่แบบโจทย์ — อย่าเพิ่งเพิ่มฟิลด์ใหม่

ข้อระดับแข่งขันที่มีอยู่ใช้ `sub` เป็นชื่อเทคนิคอยู่แล้ว (`"อสมการกับการหารลงตัว"`, `"อสมการหลายเงื่อนไข"`)
ให้ทำต่อแบบเดิม เพราะผู้เรียนกรองด้วย `sub` ได้จากหน้าเว็บทันที **โดยไม่ต้องแก้โค้ดสักบรรทัด**

> ฟิลด์ `contest` (เช่น `"IJSO"`, `"TEDET"`) เป็นของน่ามีแต่**ยังไม่ต้องทำรอบนี้** —
> ต้องแก้ `build.py` + `validate.py` + ตัวกรองใน `index.html` และมันไม่ได้เพิ่มความสามารถอะไรที่ `sub` ทำไม่ได้
> ค่อยทำตอนที่มีข้อสองระดับบนเกิน ~500 ข้อจนอยากกรองตามสนามจริง ๆ (ตอนนี้ 241)

```json
  "level": "แข่งขัน",
  "std": "<ตัวชี้วัดจริงจาก topics.json หรือ - ถ้ารวมหลายหัวข้อ>",
  "sub": "เศษเหลือจากการหาร"
}
```

**ข้อกำหนดของฟิลด์ในสองระดับบน**

- `text` — ตัวเลขทุกตัวที่ต้องใช้คำนวณต้องอยู่ในข้อความ ไม่ซ่อนอยู่ในรูปอย่างเดียว (ไม่งั้น `verify_math.py` อ่านไม่ได้)
  เศษส่วนใช้ `<span class="frac">` · เลขยกกำลังใช้ `<sup>` ตามที่คลังใช้อยู่
- `answer` — ค่าเดียว ไม่กำกวม · เขียนหน่วยได้ (ระบบตัดหน่วยให้เอง) · ห้ามตอบเป็นช่วงหรือรายการ
- `sub` — ชื่อแม่แบบจากข้อ 6 **สะกดตรงกันทุกข้อ** (ผู้เรียนกรองด้วยฟิลด์นี้)
- `std` — ต้องมีอยู่ใน `topics.json` แล้ว หรือใช้ `-` · ถ้าแม่แบบใหม่เจาะเรื่องย่อยที่ยังไม่มี ให้เพิ่ม `subtopics` ใน `topics.json` ด้วย
- `level` — `"แข่งขัน"` หรือ `"โอลิมปิก"` ตามเส้นแบ่งในข้อ 4.1

## 9. Anti-pattern — เจอแล้วตีตก

| อาการ | ทำไมถึงตก |
| --- | --- |
| **คัดลอกข้อสอบจริงจากสนามแข่ง** | ผิดลิขสิทธิ์ · ให้เขียนโจทย์ใหม่ที่วัดเทคนิคเดียวกันแทน และ**เปลี่ยนตัวเลขกับบริบทให้หมด** |
| คำตอบไม่ยูนีค | "จงหาจำนวนเต็มที่สอดคล้อง…" ที่มีหลายคำตอบ → เปลี่ยนเป็น "ผลบวกของทั้งหมด" หรือ "มีกี่จำนวน" |
| ต้องใช้ความรู้เกินชั้น | โจทย์ ม.1 ที่ต้องใช้สมการกำลังสอง = ตกทันที |
| ยากเพราะคิดเลขเยอะ ไม่ใช่เพราะคิดยาก | คูณเลข 6 หลักสามครั้ง ≠ ข้อแข่งขัน |
| คำตอบเป็นทศนิยมไม่ลงตัว | ออกแบบตัวเลขใหม่ให้ปลายทางสวย |
| ต้องเดาเจตนาผู้ออกข้อสอบ | "ประมาณเท่าใด" โดยไม่บอกว่าปัดเป็นทศนิยมกี่ตำแหน่ง |
| พึ่งรูปที่ยังไม่มีในคลัง | เขียนโจทย์ทิ้งไว้โดยไม่มีรูป = ข้อที่ตอบไม่ได้ · ให้สร้างรูปใน `build_figures.py` ก่อน |
| ชีววิทยาที่ต้องดูโครงสร้างจากภาพวาด | repo ไม่วาดโครงสร้างชีวภาพด้วย SVG — เปลี่ยนไปใช้ตาราง/ผัง หรือบรรยายด้วยข้อความ |
| ข้อแข่งขันที่ `verify_math.py` ตรวจไม่ได้ทั้งชุด | หางยาว 612 ข้อที่ค้างอยู่แล้วยาวพอ — แม่แบบใหม่ต้องมาพร้อมกฎตรวจ |
| **"การตรวจซ้ำ" ที่เทียบค่ากับตัวมันเอง** | เคยเขียนพลาดมาแล้ว 3 จุดใน `gen_advanced.py` — การตรวจที่ไม่ได้ตรวจอะไรแย่กว่าไม่มี เพราะให้ความมั่นใจปลอม |
