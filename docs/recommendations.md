## 2. ข้อบกพร่องที่ควรแก้ (เรียงตามผลกระทบ)

### ✅ 2.1 ความก้าวหน้าผูกกับ "ลำดับข้อ" ไม่ใช่ "ตัวข้อ" — **แก้แล้ว**

> ตอนนี้ทุกข้อมีฟิลด์ `id` ที่คิดจาก slug + หน่วย + แฮชของโจทย์ (ดู `qid()` ใน `tools/build.py`)
> `localStorage` คีย์ `funnymath-m1-v6` และ `funnymath-chat-v2` อ้างด้วย id ทั้งหมด
> ของที่บันทึกไว้แบบเก่าถูกย้ายให้อัตโนมัติครั้งเดียวผ่าน `questions/legacy-order.json`
> จึงแทรกข้อใหม่ไว้ตรงไหนก็ได้ · ข้อความเดิมด้านล่างเก็บไว้เป็นบันทึกว่าปัญหาคืออะไร

`localStorage` เก็บ `done`/`work`/`finalAns` โดยใช้ index ของข้อในอาร์เรย์เป็นคีย์
(`index.html` — `state.work[gidx]`) จึงต้องเพิ่มเลข `STORE_KEY` ด้วยมือทุกครั้งที่ลำดับข้อขยับ
— **ผลคือผู้เรียนเสียงานที่ทำไว้ทั้งหมดทุกครั้งที่เราเพิ่มข้อสอบ**

เอกสารเตือนเรื่องนี้ไว้ถึง 3 จุด (`README.md:56`, `docs/coverage-plan.md:229`, `:261`) ซึ่งเป็นสัญญาณว่า
มันเป็นภาระที่ควรออกแบบให้หายไป ไม่ใช่ควรเตือนให้ดีขึ้น

**ทางแก้** — ให้แต่ละข้อมี `id` ถาวร (เช่น `u07-percent-013` หรือ hash 8 ตัวจาก `text`)
แล้วเปลี่ยนคีย์ของ `localStorage` เป็น `id`

- เพิ่มฟิลด์ `id` ใน schema · `build.py` เติมให้อัตโนมัติถ้าไม่ระบุ (จาก hash ของ `text`)
- `validate.py` เพิ่มด่าน "id ต้องไม่ซ้ำและต้องไม่หายไปจากรุ่นก่อน"
- เขียน migration ครั้งเดียวใน `loadState()` แปลงข้อมูลเก่า (index-based) เป็น id-based
- ได้ผลพลอยได้: เลิกต้องเพิ่ม `STORE_KEY` ตลอดไป และลิงก์ deep link ไปข้อใดข้อหนึ่งได้ (`#q=u07-...`)

### 🟠 2.2 ไม่มีวิธีทำ/คำอธิบายในเฉลย

ทุกข้อมีแค่ `answer` (คำตอบสุดท้าย) ไม่มีขั้นตอน เมื่อผู้เรียนตอบผิด ระบบบอกได้แค่
"❌ ยังไม่ถูก ลองทบทวนวิธีทำอีกครั้ง" แล้วจบ — **นี่คือช่องว่างทางการเรียนรู้ที่ใหญ่ที่สุดของโปรเจกต์**

**ทางแก้** — เพิ่มฟิลด์ `explain` (ไม่บังคับ) เป็น array ของบรรทัดวิธีทำ แสดงใต้เฉลยเมื่อกด "ดูเฉลย"
และเพิ่มฟิลด์ `hint` (ไม่บังคับ) ที่กดดูได้โดยไม่ต้องใส่รหัสผ่าน

```json
{
  "text": "จงหาค่าของ (-8) + 15 - (-6)",
  "answer": "13",
  "hint": "ลบด้วยจำนวนลบ = บวกด้วยจำนวนบวก",
  "explain": ["(-8) + 15 - (-6)", "= (-8) + 15 + 6", "= 7 + 6", "= 13"]
}
```

เริ่มจากหน่วยที่ผู้เรียนพลาดบ่อยก่อน (1, 3, 6, 7) ไม่ต้องทำครบ 610 ข้อรวดเดียว
ให้ `validate.py` รายงานเป็นตัวเลข "มี explain แล้ว X/610 ข้อ" เพื่อติดตามความคืบหน้า

## 3. ฟีเจอร์ที่ควรเพิ่ม (เรียงตามคุ้มค่าต่อแรงที่ลง)

### 3.1 โหมดทำข้อสอบจับเวลา (Exam mode) — คุ้มที่สุด

ตอนนี้ทำได้แค่ไล่ทำทีละข้อไปเรื่อย ๆ ไม่มีอะไรจำลอง "การสอบ" ทั้งที่คลังมีถึง 610 ข้อ

- สุ่มชุด N ข้อ (20/30/50) จากตัวกรองที่เลือกไว้ · กำหนดเวลา · ซ่อนปุ่ม "ดูเฉลย" ระหว่างสอบ
- ครบเวลา/ส่งข้อสอบ → สรุปคะแนน, ข้อที่ผิด, เวลาที่ใช้, แยกผลตามหน่วยและตามตัวชี้วัด
- reuse `checkAnswer()` เดิมได้ทั้งหมด แทบไม่ต้องเขียนตรรกะใหม่

### 3.2 ทบทวนข้อที่ตอบผิด

`state.checked` เก็บ `'ok' | 'no' | 'manual'` ของทุกข้ออยู่แล้ว แต่ไม่มีอะไรใช้ข้อมูลนั้นเลย
เพิ่มตัวกรองชั้นที่ 5 "สถานะ": ทั้งหมด / ยังไม่ทำ / ทำแล้ว / **ตอบผิด** — แรงน้อยมาก ผลตรงกับสิ่งที่ผู้เรียนต้องการที่สุด

### 3.3 หน้าสรุปจุดอ่อน (Dashboard)

แถบความก้าวหน้าตอนนี้บอกแค่ "ทำแล้วกี่ข้อ" ของรายการที่กรองอยู่
ควรมีหน้าสรุป: ความถูกต้องแยกตามหน่วย · แยกตามตัวชี้วัด (`std`) · แยกตามระดับ
พร้อมข้อเสนอ "ควรทบทวนหน่วย X" — ข้อมูลมีอยู่ครบใน `state.checked` แล้ว

### 3.4 ส่งออก/นำเข้าความก้าวหน้า

ทุกอย่างอยู่ใน `localStorage` เท่านั้น — เปลี่ยนเครื่อง/ล้าง browser/เพิ่ม `STORE_KEY` = หายหมด
เพิ่มปุ่ม "บันทึกไฟล์ความก้าวหน้า (.json)" และ "โหลดกลับ" ให้ครูเก็บงานนักเรียนได้ด้วย

### 3.5 ช่องค้นหาข้อสอบ

## 4. คุณภาพโค้ดและ repo

### 4.1 การเข้าถึง (Accessibility)

หน้าเว็บทำ `aria-expanded`/`aria-controls` ในแผงตัวกรองไว้ดีแล้ว แต่ modal ยังขาด

- `#overviewOverlay` และ `#pwOverlay` ไม่มี `role="dialog"` / `aria-modal="true"` / `aria-labelledby`
- ไม่มี focus trap และ **กด Esc ปิด modal ไม่ได้** — ตัวจัดการ keydown (`index.html`)
  `return` ทิ้งทันทีเมื่อ modal เปิดอยู่ ทำให้ Esc ใช้ได้แค่กับแผงตัวกรอง
- `#checkResult` ไม่มี `aria-live="polite"` — ผู้ใช้ screen reader ไม่รู้ผลการตรวจคำตอบ
- ปิด modal แล้วไม่คืน focus ไปยังปุ่มที่เปิดมัน

### 4.2 รหัสผ่านเฉลยเป็นแค่ "ที่กั้น" ไม่ใช่ความปลอดภัย

`ANSWER_PASSWORD = "2569"` อยู่เป็น plaintext และ **เฉลยทุกข้ออยู่ใน DOM ตั้งแต่ต้น**
(`<div class="answer">` แค่ถูกซ่อนด้วย CSS) — เปิด View Source หรือ DevTools ก็เห็นครบทั้ง 610 ข้อ

ถ้ายอมรับได้ในบริบทการใช้งานจริง ควร **ระบุไว้ตรง ๆ ใน README** ว่าเป็นเพียงที่กั้นไม่ให้เผลอกด
ถ้าต้องการให้กันได้จริง ต้องเข้ารหัสฟิลด์ `answer` ด้วย AES-GCM (WebCrypto) โดยใช้รหัสผ่านเป็น key
แล้วถอดรหัสตอนปลดล็อก — `build.py` ทำขั้นตอนเข้ารหัสได้ตอน build (แต่ `validate.py` ด่านที่ 7
ต้องอ่านจากไฟล์ JSON ต้นทางแทน `index.html`)

### 4.3 CI

> **หมายเหตุ (ปรับแล้ว)** — repo นี้เลิกใช้ GitHub Actions ทั้งหมดแล้ว เพราะบัญชีเรียก runner
> ไม่ได้ · การตรวจย้ายมาที่ `tools/check.sh` + git hook `.githooks/pre-push` และ Pages
> เสิร์ฟจากแบรนช์ · ข้อเสนอด้านล่างเก็บไว้เผื่อวันที่กลับไปใช้ Actions ได้

```yaml
permissions:          # อยู่ระดับ workflow — job "validate" ที่รันบน PR ได้สิทธิ์เกินจำเป็น
  contents: read
  pages: write
  id-token: write
```

- ย้าย `pages: write` / `id-token: write` ไปไว้ที่ job `deploy` เท่านั้น ให้ job `validate` มีแค่ `contents: read`
- `npm install jsdom --no-save` ไม่ได้ pin เวอร์ชัน — jsdom ออก major ใหม่เมื่อไหร่ชุดตรวจพังโดยไม่มีอะไรในโค้ดเปลี่ยน
  (ยังค้างอยู่ · `tools/check.sh` ก็ใช้คำสั่งเดียวกัน)
  ควรใส่ `jsdom@^26` หรือทำ `package.json` + `package-lock.json` แล้วใช้ `npm ci` พร้อม `actions/setup-node` cache
- เพิ่ม `actions/cache` สำหรับ npm และเพิ่ม **Dependabot** (`.github/dependabot.yml`) ให้อัปเดต GitHub Actions
- พิจารณาเพิ่ม lint: `ruff` สำหรับ Python (4 ไฟล์) และ `eslint` หรืออย่างน้อย `prettier --check` สำหรับ JSON คลังข้อสอบ

### 4.4 ยังไม่มีเทสต์ของตัว `tools/` เอง

`validate.py` และ `build.py` เป็นด่านสุดท้ายที่กันคลังข้อสอบพัง แต่ไม่มีอะไรตรวจว่าสองตัวนี้ทำงานถูก
ควรเพิ่ม `tools/test_tools.py` (pytest) ที่ป้อนคลังข้อสอบปลอมแล้วยืนยันว่า **จับ error ได้จริง** —
อ้างชื่อรูปที่ไม่มี, `[[fig]]` ที่ไม่มี `figure`, โจทย์ซ้ำ, ข้อปรนัยที่มี 3 ตัวเลือก, `level` ผิดค่า

### 4.5 ไฟล์สำเนาภาษาไทยขนาด 615 KB

`ข้อสอบคณิตศาสตร์_ม1.html` เหมือน `index.html` ทุกไบต์ ทำให้ทุก commit ที่แตะข้อสอบมี diff สองเท่า
และ payload ของ GitHub Pages โตเป็นสองเท่า

ทางเลือก: ลบไฟล์สำเนาออก แล้วใส่ปุ่ม "ดาวน์โหลดไฟล์ไว้ใช้ออฟไลน์" ในหน้าเว็บที่สร้างไฟล์จาก
`document.documentElement.outerHTML` ผ่าน Blob พร้อมตั้งชื่อไฟล์ภาษาไทย — ได้ผลเดิมโดยไม่ต้องเก็บสำเนา
(ถ้ายังอยากเก็บสำเนาไว้ ก็ไม่ใช่ปัญหาใหญ่ เพราะ repo ทั้งหมดยังแค่ 512 KB หลังบีบอัด)
