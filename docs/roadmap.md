และ `difficulty_tier` 1–4 ที่สเปกเสนอ ตรงกับ ง่าย/กลาง/ยาก/แข่งขัน ที่ทำไว้แล้ว ไม่ต้องแก้

## สามข้อสรุปที่กำหนดลำดับงาน

### 1. ไฟล์เดียวไปต่อไม่ไหว — ต้องแยกก่อนเติมเนื้อหา

```
index.html วันนี้      2.33 MB   (QUESTIONS 2.13 MB · 741 bytes/ข้อ · 3,015 ข้อ)
ครบสเปก 600 ข้อ/วิชา   ~15 MB   ในไฟล์เดียว + สำเนาออฟไลน์อีก 15 MB
```

มือถือต้องโหลดและแจง JSON 15 MB ทุกครั้งที่เปิด ทั้งที่จะทำข้อสอบวิชาเดียว
**ต้องแยกก่อน** ไม่งั้นเนื้อหาที่เติมไปทุกเฟสจะต้องรื้อทำใหม่

### 2. สเปกไม่ครบตัวชี้วัด — ใช้เป็นแผนที่หัวข้อ ไม่ใช่ตัวตัดสิน

สเปกลิสต์เรขาคณิต ม.2 ไว้ 6 หัวข้อ แต่**ตกตัวชี้วัด ค 2.2 ม.2/1 (การสร้างทางเรขาคณิต)**
ซึ่งมีข้อสอบอยู่แล้ว 120 ข้อ · `MATH_STD` ใน `tools/validate.py` ยังต้องเป็นตัวตัดสินสำหรับ
คณิต/วิทย์ ส่วน `topics.json` เป็นชั้นแผนที่หัวข้อทับลงไป ไม่ใช่แทนที่

### 3. สเปกจับช่องว่างของคลังได้จริง 1 จุด

ม.3 สถิติ (ค 3.1 ม.3/1) มีควอร์ไทล์/IQR ครบ 35 ข้อ แต่**ไม่มีแผนภาพกล่อง (box plot)
เปอร์เซ็นไทล์ และค่านอกเกณฑ์เลยสักข้อ** ทั้งที่อยู่ในตัวชี้วัดเดียวกัน

> **HSK:** สเปกเขียนไว้ว่า HSK 3.0 "มีผลบังคับใช้ 1 ก.ค. 2026" ซึ่งผ่านมาแล้ว
> ถ้าทำภาษาจีนต้องตั้งต้นที่ **HSK 3.0** ไม่ใช่ 2.0 (จำนวนคำต่างกันเกือบเท่าตัว)

> **วรรณคดี:** สเปกเตือนว่า "อิเหนา ตอนศึกกะหมังกุหนิง" เป็นของ **ม.4** ห้ามจัดเข้า ม.3

## เฟส 0 — รายละเอียดการออกแบบ

**เป้าหมาย:** เปิดหน้าแรกเร็วเท่าเดิมหรือเร็วกว่า และโหลดข้อสอบเฉพาะวิชาที่กด

| ไฟล์ | เนื้อหา |
| --- | --- |
| `index.html` | โค้ด + CSS + **manifest** (วิชา ชื่อหน่วย จำนวนข้อ) — ไม่มีตัวข้อสอบ |
| `data/<slug>.json` | ข้อสอบของวิชานั้น โหลดตอนกดเข้าวิชา |
| `ข้อสอบ…_ม1.html` | **รวมทุกอย่างไว้ในไฟล์เดียวเหมือนเดิม** เพื่อให้เปิดออฟไลน์จาก `file://` ได้ |

`fetch()` บน `file://` ถูก CORS บล็อก สำเนาออฟไลน์จึงต้องเป็นไฟล์รวมต่อไป
`tools/build.py` เขียนทั้งสองรูปแบบจากคลังชุดเดียวกัน

### สิ่งที่ต้องแก้ตามมา

- **`state.done` ต้องเก็บเป็น `id` ไม่ใช่ `gidx`** — หน้าแรกต้องบอกความก้าวหน้าของวิชาที่ยัง
  ไม่ได้โหลด ซึ่งไม่มี `gidx` · การย้ายมาใช้ id ตั้งแต่ #16 ทำให้แก้ตรงนี้ได้ และจะได้ตัด
  ชั้นแปลง `byId`/`byIdx` ทิ้งไปเลย
- `QUESTIONS` เริ่มว่าง โหลดวิชาแล้ว append + สร้าง index ใหม่ · ทุกอย่างวาดผ่าน `renderAll()`
  อยู่แล้วจึงกระทบไม่มาก
- ต้องมีสถานะ "กำลังโหลดวิชา…" และเส้นทางที่โหลดไม่สำเร็จ (เน็ตหลุด/ไฟล์หาย)
- `dom_test.cjs` ต้อง stub `fetch` ของข้อมูลวิชาเพิ่ม (มี stub ของ AI อยู่แล้ว)

### เกณฑ์ว่าเฟส 0 เสร็จ

- หน้าแรกแสดงครบทุกวิชา จำนวนข้อรายหน่วย และความก้าวหน้า **โดยไม่โหลด `data/*.json` เลย**
- กดเข้าวิชาแล้วโหลดเฉพาะไฟล์ของวิชานั้น
- สำเนาออฟไลน์เปิดจาก `file://` แล้วใช้ได้ครบทุกวิชาเหมือนเดิม
- ความก้าวหน้าที่บันทึกไว้เดิมไม่หาย (ทั้งแบบ v5 และ v6)
- `check.sh` ผ่านครบทุกขั้น

## เฟส 1 — รายละเอียดการออกแบบ

**เป้าหมาย:** ย้ายรายการตัวชี้วัดออกจากโค้ด ให้ด่านตรวจความครอบคลุมใช้ได้กับทุกวิชา
ไม่ใช่แค่คณิตศาสตร์ที่เคยฮาร์ดโค้ดไว้ใน `MATH_STD`

`questions/topics.json` — 127 หัวข้อ ครอบคลุม 5 วิชาที่มีอยู่ (คณิต ม.1–ม.3 · วิทย์ ม.1–ม.2)

| ฟิลด์ | ใช้ทำอะไร |
| --- | --- |
| `std` | ตัวชี้วัด — กุญแจที่ใช้จับคู่กับข้อสอบ |
| `status` | `active` = ต้องมีข้อสอบแล้ว · `planned` = ตั้งใจว่ายังไม่ทำ |
| `needs_svg` / `svg_type` | หัวข้อนี้ควรมีรูปประกอบไหม และเป็นรูปแบบไหน (กติกาจากสเปก) |
| `subtopics` | เรื่องย่อยในตัวชี้วัดเดียวกัน จับด้วยคำสำคัญใน `match` |

**ใช้ JSON ไม่ใช่ YAML** ตามที่สเปกเสนอ — repo นี้ไม่มี dependency ของ Python เลย
การเพิ่ม PyYAML แลกกับความสะดวกของ syntax ไม่คุ้ม

### สิ่งที่ด่านนี้ดักได้ (และ `MATH_STD` เดิมดักไม่ได้)

- ตัวชี้วัด **วิทยาศาสตร์** ที่ข้อสอบหายไปหมด — เดิมไม่มีใครตรวจเลย (94 ตัวชี้วัด)
- ตัวชี้วัดที่มีข้อสอบแต่ไม่มีในแผนที่ (พิมพ์ผิด/เพิ่มใหม่แล้วลืมลงทะเบียน)
- **เรื่องย่อยที่ขาด ทั้งที่ตัวชี้วัดนั้นมีข้อสอบแล้ว** — คือช่องว่างที่สเปกจับได้
  (ค 3.1 ม.3/1 มีควอร์ไทล์ 35 ข้อ แต่ไม่มีแผนภาพกล่อง เปอร์เซ็นไทล์ ค่านอกเกณฑ์)
- หัวข้อที่ควรมีรูปแต่ยังไม่มีสักข้อ — รายงานเป็นงานค้าง ไม่ใช่ข้อผิดพลาด
  (คณิต ม.3 ขาด 9 หัวข้อ · วิทย์ ม.1 ขาด 33 · วิทย์ ม.2 ขาดทั้ง 54 — ยังไม่มี SVG เลยสักรูป)

`validate.py --selftest` (รันอัตโนมัติก่อนตรวจจริงทุกครั้ง) ป้อนแผนที่สมมุติ 15 เคส
เข้าไปตรวจว่าด่านนี้ยัง**ดักของผิดได้จริง** ไม่ใช่แค่ผ่านเพราะไม่มีอะไรให้ดัก

### สิ่งที่ยังไม่ทำในเฟสนี้ (ตั้งใจ)

`planned_courses` เก็บแค่ชื่อวิชา/ชั้น/เฟส **ไม่ใส่ตัวชี้วัดของวิชาที่ยังไม่เริ่ม**
เพราะต้องเทียบหลักสูตรจริงตอนลงมือทำ การเดารายการไว้ก่อนจะกลายเป็นด่านที่ตรวจของผิด
