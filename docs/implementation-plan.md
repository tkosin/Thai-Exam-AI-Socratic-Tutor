## เฟส 6 — เตรียมระบบ (ไม่มีข้อสอบใหม่สักข้อ)

### 6.1 ขยาย `STD_RE` และ `PREFIX` ให้รับทั้ง 8 กลุ่มสาระ

`tools/validate.py`

```python
# ค=คณิต · ว=วิทย์/เทคโนโลยี · ท=ไทย · ส=สังคม · พ=สุขศึกษา · ศ=ศิลปะ · ง=การงานอาชีพ · ต=ต่างประเทศ
STD_RE = re.compile(r"^([ควทสพศงต] \d\.\d [มป]\.\d/\d{1,2}|-)$")

PREFIX = {"คณิตศาสตร์": "ค", "วิทยาศาสตร์": "ว", "เทคโนโลยี": "ว",
          "ภาษาไทย": "ท", "สังคมศึกษา ศาสนา และวัฒนธรรม": "ส",
          "สุขศึกษา": "พ", "ศิลปะ": "ศ", "การงานอาชีพ": "ง", "ภาษาอังกฤษ": "ต"}
```

**ต้องมีเทสต์กันการถอยหลัง** — `validate.py --selftest` มีอยู่แล้ว เพิ่มเคส: ตัวชี้วัดอักษรแปลก
(`ก 1.1 ม.1/1`) ต้องไม่ผ่าน · วิชาภาษาไทยที่ใส่ `ค 1.1` ต้องไม่ผ่าน

> **ชื่อวิชา `สุขศึกษา` ไม่ใช่ `สุขศึกษาและพลศึกษา`** — ตั้งใจ เพราะคลังไม่ครอบคลุมพลศึกษา
> ชื่อวิชาต้องบอกความจริงกับผู้เรียน ไม่ใช่ยืมชื่อกลุ่มสาระเต็มมาแล้วครอบคลุมครึ่งเดียว

### 6.2 ฟิลด์ `explain` — บังคับกับวิชาใหม่ ตั้งแต่วิชาแรก

`tools/validate.py:35` แยกเป็นสองชุด เพื่อไม่ให้ 5,175 ข้อเดิมพังทันที:

```python
FIELDS = ("subject", "grade", "unit", "uname", "sub",
          "text", "answer", "level", "std", "tag")
# วิชาที่ตั้งหลังกติกา explain — ทุกข้อต้องมีคำอธิบายวิธีคิด ไม่มีข้อยกเว้น
FIELDS_EXPLAIN = FIELDS + ("explain",)
EXPLAIN_REQUIRED = {"ภาษาไทย", "สังคมศึกษา ศาสนา และวัฒนธรรม", "สุขศึกษา",
                    "ศิลปะ", "การงานอาชีพ", "ภาษาอังกฤษ", "เทคโนโลยี"}
```

**เกณฑ์คุณภาพของ `explain`** (ตรวจด้วยสคริปต์ได้):

- ยาวอย่างน้อย ~40 ตัวอักษร — กัน `"ตอบ ก"` ที่ไม่ได้อธิบายอะไร
- **ห้ามเป็นการทวนตัวเลือกที่ถูกเฉย ๆ** — ถ้า `explain` เป็นสับเซตของข้อความตัวเลือกที่ถูก ให้ตก
- ต้องบอกว่า**ทำไมตัวลวงถึงผิด** อย่างน้อยหนึ่งตัว สำหรับข้อระดับ `ยาก` ขึ้นไป

### 6.3 แสดงคำอธิบายตอนตอบผิด — **ไม่ต้องใส่รหัสผ่าน**

`index.html:2718` `MSG.no` ตอนนี้คือทางตัน:

> ❌ ยังไม่ถูก ลองทบทวนวิธีทำอีกครั้ง — ถ้าติดจริง ๆ กด "ดูเฉลย" (ต้องใส่รหัสผ่าน)

**ข้อเสนอ: แยก "คำอธิบาย" ออกจาก "เฉลย" ให้ขาด**

| | ต้องใส่รหัสผ่าน (`ANSWER_PASSWORD`) | เหตุผล |
| --- | --- | --- |
| **คำอธิบายวิธีคิด** (`explain`) | **ไม่ต้อง** | เด็กที่ตอบผิดต้องได้เรียนรู้ทันที ไม่ใช่รอครู |
| **ตัวคำตอบ** (`answer`) | ต้อง (เหมือนเดิม) | ที่กั้นไม่ให้เผลอกดดูก่อนคิด — เจตนาเดิมของ repo |

นี่คือหัวใจของเฟสนี้ · คำอธิบายที่ล็อกไว้หลังรหัสผ่านที่นักเรียนไม่มี = ไม่มีคำอธิบาย

**เทสต์ที่ต้องเพิ่มใน `dom_test.cjs`** — ตอบผิดในข้อที่มี `explain` แล้ว
คำอธิบายต้องปรากฏโดยไม่แตะรหัสผ่าน · และตัวคำตอบต้อง **ยัง** ไม่ปรากฏ

### 6.4 สถานะ `practical` ใน `topics.json`

`validate.py:86` ขยาย enum เป็น `active` / `planned` / `practical`

- `practical` = ตัวชี้วัดมีจริงในหลักสูตร แต่ **ประเมินด้วยข้อเขียนไม่ได้โดยหลักการ**
- ด่านความครอบคลุม (`validate.py:125–147`) **ต้องไม่บังคับให้มีข้อสอบ** และ
  **ต้องไม่รายงานเป็นงานค้าง**
- `check_official()` (`validate.py:162`) **ยังนับรวมในยอดตัวชี้วัดเหมือนเดิม** —
  ความครอบคลุมจึงยังพูดความจริงว่าหลักสูตรมีกี่ตัว เราทำได้กี่ตัว
- ต้องมีฟิลด์ `practical_reason` บังคับคู่กัน เขียนเป็นข้อความว่าทำไมประเมินไม่ได้
  ("ตัวชี้วัดคือการเล่นกีฬาจริง") — กันการใช้ `practical` เป็นที่ซุกตัวชี้วัดที่แค่ทำยาก

## เฟส 7–10 — เนื้อหา

ทุกวิชาใช้ขั้นตอนเดียวกัน (ทำตาม `tech-m3` ซึ่งผ่านมาแล้ว):

1. คัดตัวชี้วัดรายชั้นจากเอกสาร สพฐ. ฉบับปรับปรุง 2560 **ตรงตัว** ลง `topics.json`
   พร้อมฟิลด์ `official` (ยอดรวม · สาระที่มี · สาระที่ยืนยันว่าไม่มี) —
   `_readme` ของไฟล์นั้นห้ามเดาไว้ล่วงหน้า ต้องเทียบตอนลงมือ
2. ตั้งหัวข้อที่ประเมินด้วยข้อเขียนไม่ได้เป็น `practical` พร้อม `practical_reason`

4. เพิ่มวิชาใน `questions/courses.json` · สร้าง `questions/<slug>/unit-NN-*.json`
5. `python3 tools/build.py` แล้ว `bash tools/check.sh` ต้องผ่านทุกขั้น
